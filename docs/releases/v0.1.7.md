# v0.1.7: Working Compiled Binaries + De-Guardianed Hooks

**Date:** 2026-06-26

This release makes the cross-platform `bun --compile` release binaries work as
**full standalone artifacts** — including the HTTP server — and adds a release
gate so they can't silently regress again.

## Highlights

- **Full standalone single-file binaries.** Each `bun --compile` binary now
  starts cleanly, reports its own version/identity, and runs every command —
  `version`, `health`, `doctor`, `envinfo`, **and `serve`** — from anywhere, not
  just a repo checkout. This builds on `@fulmenhq/tsfulmen` **v0.4.0**, whose
  compile-safe SSOT asset embedding resolves schemas, JSON-Schema metaschemas,
  and foundry catalogs (including the signals catalog) without the filesystem.
- **Real config validation in the binary.** Configuration is now schema-validated
  inside the compiled binary (the JSON-Schema metaschema is embedded), so invalid
  config is rejected — e.g. `TUVAN_SERVER_PORT=abc tuvan doctor --json` reports a
  failed check and exits non-zero instead of silently passing.
- **Release smoke test asserts the server binds.** `build:all` (and the release
  workflow) runs the freshly built host binary's `version`, `doctor --json`, and
  `serve` from outside the repo and fails the build unless they behave correctly.
  The `serve` check now confirms the server actually **binds** (data + control
  plane) rather than refusing — catching startup crashes, version regressions,
  broken config loading, and a non-functional server before a release ships.
- **Diagnostics are embedded-aware.** `version`, `health`, `doctor`, and
  `envinfo` read the binary's embedded identity/version/config (and the injected
  tsfulmen version) instead of reporting "unknown" or "misinstalled". `--json`
  output is clean (config diagnostics go to stderr).
- **Hooks without guardian.** The goneat git hooks were regenerated without the
  guardian browser-approval intercept, matching direct-push workflows.

## How the binary stays self-contained

A single-file binary carries no on-disk `VERSION`, `.fulmen/app.yaml`, `config/`,
or `schemas/` tree. The build (`scripts/build-all.ts`) injects those via
`bun build --define`, and at runtime:

- **Identity** is registered from the build-injected `app.yaml` and validated
  against tsfulmen's embedded app-identity schema (no skip-validation needed).
- **Config** is loaded from the build-embedded defaults + schema passed *inline*
  to `loadConfig({ defaults, schema })` (tsfulmen ≥ 0.3.3), with full schema
  validation against the embedded metaschema.
- **Foundry catalogs / signals** resolve from tsfulmen's embedded assets, so the
  signal manager and HTTP server start normally.

`TSFULMEN_ASSET_MODE` (default `auto`) selects on-disk assets in dev/node runs
and embedded assets inside the binary automatically.

## Dependency Changes

| Package              | Previous | Updated | Type       |
| -------------------- | -------- | ------- | ---------- |
| `@fulmenhq/tsfulmen` | 0.3.0    | 0.4.0   | production |

`yaml` is a direct dependency (already present transitively) used to parse the
build-time embedded config defaults for the inline `loadConfig` path.

## Notes for Template Consumers

- This repo is meant to be CDRL'd (Clone → Degit → Refit → Launch); compiled
  binaries (`make build:all`) embed `.fulmen/app.yaml`, `VERSION`, and the
  config defaults/schema so the binary is self-contained — server included.
- Re-run `make hooks-ensure` (or `goneat hooks generate && goneat hooks
  install`) if you want the de-guardianed hooks.
- Versions 0.1.3–0.1.6 were unreleased internal iterations and were never
  tagged; v0.1.7 is the next tagged release after v0.1.2.
