# v0.1.7: Working Compiled Binaries + De-Guardianed Hooks

**Date:** 2026-06-17

This release makes the cross-platform `bun --compile` release binaries actually
work as standalone artifacts, and adds a release gate so they can't silently
regress again.

## Highlights

- **Compiled binaries fixed for CLI/diagnostic use.** The standalone single-file
  binaries previously crashed at startup or ran the wrong CLI. Adopting
  `@fulmenhq/tsfulmen` v0.3.2 (string-metrics-wasm 0.3.10 + compile-safe
  CLIs/bins) plus build-time embedding of identity, version, and config assets
  means each binary now starts cleanly, reports its own version/identity, and
  runs `version`, `health`, `doctor`, and `envinfo` from anywhere — not just a
  repo checkout.
- **Release smoke test.** `build:all` (and the release workflow) now runs the
  freshly built host binary's `version`, `doctor --json`, and `serve` from
  outside the repo and fails the build unless they behave correctly — catching
  startup crashes, version regressions, and broken config loading before a
  release ships.
- **Diagnostics are embedded-aware.** `health` and `doctor` recognize a
  compiled binary's embedded identity/version/config instead of reporting it as
  unhealthy or misinstalled. `--json` output is clean (config diagnostics go to
  stderr).
- **Hooks without guardian.** The goneat git hooks were regenerated without the
  guardian browser-approval intercept, matching direct-push workflows.

## Scope: standalone binary vs. server

The `bun --compile` single-file binaries are **CLI/diagnostic tools** in this
release (`version`, `health`, `doctor`, `envinfo`). The **HTTP server (`serve`)
is not yet supported in the standalone binary** — `@fulmenhq/tsfulmen` loads
several SSOT assets (foundry catalogs, schemas) from the filesystem, which are
not present in a single-file binary. Run the server from a Node/npm install
(`node dist/index.js serve`), where those assets are on disk. In the standalone
binary, `serve` exits with a clear message pointing to the npm/Node path.
Full standalone server support is tracked upstream (tsfulmen compile-safe
assets).

| `@fulmenhq/tsfulmen` | 0.3.0    | 0.3.2   | production |

`yaml` is a direct dependency now (already present transitively) used to parse
the build-time embedded app identity.

## Notes for Template Consumers

- This repo is meant to be CDRL'd (Clone → Degit → Refit → Launch); compiled
  binaries (`make build:all`) now embed `.fulmen/app.yaml`, `VERSION`, and the
  config defaults/schema so the binary is self-contained.
- Re-run `make hooks-ensure` (or `goneat hooks generate && goneat hooks
  install`) if you want the de-guardianed hooks.
- Versions 0.1.3–0.1.6 were unreleased internal iterations and were never
  tagged; v0.1.7 is the next tagged release after v0.1.2.
